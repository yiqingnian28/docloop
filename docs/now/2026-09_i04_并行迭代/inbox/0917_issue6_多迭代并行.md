# issue #6 · 支持多个活跃迭代并行管理与独立结算（跟进 OQ-1）

- 作者：yiqingnian28 · 2026-09-18T01:42:57Z · https://github.com/yiqingnian28/docloop/issues/6

## 使用场景

同一项目需要同时推进两个迭代：迭代 A 尚在验收或收尾，迭代 B 已开始设计与开发。两者有各自的目标、任务、待确认事项和结束时间，需要独立跟踪、独立结算。

将两条工作线合并为一个迭代可以满足部分场景，但无法表达两个迭代独立的生命周期。

## 当前限制

- [use-cases.md](https://github.com/yiqingnian28/docloop/blob/main/docs/truth/mechanism/use-cases.md) 已将“多条任务线/多迭代并行时 now/ 怎么组织”列为 OQ-1，并注明 v1 假设单迭代串行。
- [layers.md](https://github.com/yiqingnian28/docloop/blob/main/docs/truth/mechanism/layers.md) 规定 now/ 只活一个迭代，结算时整体冻结进 past/。
- [lifecycle.md](https://github.com/yiqingnian28/docloop/blob/main/docs/truth/mechanism/lifecycle.md) 要求开迭代前 now/ 为空，并在结算后开新迭代。
- [docloop_lint.mjs](https://github.com/yiqingnian28/docloop/blob/main/skills/docloop/scripts/docloop_lint.mjs) 固定读取 now/iteration.md；now/ 顶层白名单不允许直接添加迭代子目录。

因此，当前缺少两个活跃迭代的隔离方式，也没有定义结算其中一个时如何保留另一个的在途文档。

## 期望行为

1. 能列出同一项目所有活跃迭代，并明确本次工作属于哪个迭代；Agent 按需读取目标迭代，避免自动加载所有并行工作的上下文。
2. 每个迭代独立维护目标、范围、任务、Open Questions、CH、inbox 和临时产物。
3. 结算或预算触发提前结算时，只冻结对应迭代；其他活跃迭代保持原状，未完任务的结转目标明确。
4. 共享 truth 的变更有跨迭代冲突检查规则，避免两个迭代分别裁决后互相覆盖。
5. T/CH 等编号在并行创建时不冲突；引用在所有活跃迭代与 past 中都可解析。
6. 明确每迭代预算、开工必读集预算以及活跃文档总量的约束，提供配套 lint 与迁移说明。

## 可讨论的方案

可考虑将 now/ 作为活跃迭代容器，以迭代子目录隔离 iteration.md、tasks/、changes/、inbox/ 等，并提供轻量导航入口；truth/ 继续共享，past/ 按迭代冻结。

这只是候选方向，不预先限定目录结构。希望先明确多迭代生命周期、共享真相更新和编号分配，再同步规范、skill 模板与 lint；同时保留简单单迭代项目的使用便利。

## 验收示例

- A、B 同时活跃时，任务和变更能明确归属，分别通过体检。
- A 结算后，A 的摘要与冻结包可追溯；B 的文档、状态和链接不受影响。
- A、B 修改同一 truth 规则时，冲突能被识别并交由裁决，不会静默覆盖。
- 单迭代项目有兼容方式或明确迁移路径。

本议题跟进现有 OQ-1。与 #5 的冻结包内部组织相关，但重点是活跃迭代隔离与独立结算。
