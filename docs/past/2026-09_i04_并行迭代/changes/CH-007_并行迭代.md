# CH-007 · 并行迭代（源自 issue #6）

- 日期：2026-09-17 · 起草：AI · 裁决人：用户

## 变化

GitHub issue #6 跟进 OQ-1：同一项目要同时推进两个迭代，各自独立跟踪、独立结算；现行 now/ 只活一个迭代、开迭代前须为空、lint 白名单不许子目录。用户会话补充：并行对象是**作用域互斥的独立子模块**，不对同一模块或有耦合依赖的模块并行。据此把"通用多迭代"收窄为"作用域互斥的并行迭代"，五个变化点：

1. **作用域互斥替代冲突检查**：iteration.md frontmatter 声明 `scope:`（拥有的 truth 路径 glob）；两个活跃迭代 scope 重叠→红；改写 scope 外的模块 truth→黄；decisions / README / glossary / sources 等共享文件豁免。跨作用域改动两条路：在拥有方迭代开 CH，或经 CH 扩 scope。CH 冲突检查面从"本迭代 CH"扩到"所有活跃迭代的 CH"。
2. **目录统一一层**：`now/<YYYY-MM_i##_标题>/`，内部同现 now/；与 past/ 命名一致，结算 = 一次 `git mv`。单迭代项目不设兼容模式；`ls now/` 即活跃迭代列表，不设索引文件。不变量 2 改口："每个迭代结束其目录必整体移出 now/"。
3. **预算按迭代目录**：now 总量按单迭代目录计；开工必读集按任务包所在迭代的 iteration.md 实算；提前结算按单迭代触发；活跃迭代数超阈→黄，防"用并行逃避结算"。
4. **结算只冻结该目录**：未完任务结转目标显式写（新迭代或指定活跃迭代），summary 记一行；"开迭代前 now/ 为空"改为"该迭代目录不存在"。
5. **编号不变**：T/CH 全仓递增 + lint 查重已覆盖并行撞号，不引入迭代前缀。
