# 仪式 · 开迭代与结算

docloop 以迭代（几天~一周）为心跳。now/ 下每个迭代一个目录 `YYYY-MM_i##_<标题>/`（命名与 past/ 一致）；多个迭代可以并行，唯一前提是**作用域互斥**（见文末）。

## 开迭代

- 建目录 `now/YYYY-MM_i##_<标题>/`（i## 全仓递增，含 past/；月份取开迭代当月），内建 `tasks/ changes/ inbox/`。
- 按 templates/iteration.md 写 `iteration.md`：frontmatter `scope:`（本迭代拥有的 truth 路径 glob，相对 docs/truth，与其他活跃迭代不得重叠）；正文写目标、范围（覆盖哪些账本条目 / 模块）、任务清单（T-### 全局递增）、Open Questions。
- 单迭代项目同一布局，now/ 下只有一个目录；`ls now/` 就是活跃迭代清单，不设索引文件。

## 结算清单（按序全过才算关闭）

1. **truth 回写定稿**：设计变化全部改写进 truth，无欠账 Reverse Sync。
2. **账本对账**：迭代范围内每条条目有归属——任务 + 验收证据 / 显式挂起 / 显式否决，**没有一条默默消失**。
3. **inbox 清仓**：每份素材三选一——已出 CH / 显式作废 / 结转到接收迭代的 inbox。
4. **决策增补**：本迭代拍板的长期决策进 `truth/decisions.md`。
5. **写 summary**（模板 templates/summary.md，≤120 行）：做成了什么、关键决策、CH 清单、未了事项（含体检黄项）——它是本迭代唯一可被日常引用的史料。
6. **冻结**：本迭代目录整体搬进 `past/`（目录名不变，一次 `git mv`；任务包连 checkpoint、CH、inbox 一起封存），其他活跃迭代不动。**未完任务包例外**：移动结转进指定的接收迭代（新开的或另一个活跃的，任务须落在其 scope 内；checkpoint 随身走，不留冻结副本），summary 记一行"T-### 未完结转 i##"。
7. **开新迭代**：有后续工作就按上面的开迭代仪式建新目录；结转了未完任务时接收迭代必须已存在。
8. **体检无红**：红（违反不变量 / 超硬预算）阻断关闭；黄允许关闭但必须逐条写进 summary 未了事项（关闭前允许修订本次 summary）——体检过了，本次结算才算关闭。

## 强制提前结算

没到日历终点但某个迭代目录总量超预算（默认 2000 行，inbox 只计件数）→ **该迭代必须提前结算**：已完成部分按清单结算，未完任务按第 6 步结转。提前结算是完整的小结算，不是批量搬文件。这是防"迭代拖长、文档撑爆上下文"的硬闸门——预算触发，不只靠日历。

## 并行迭代 = 作用域互斥的迭代

- 每个迭代用 `scope:` 声明自己拥有的 truth 路径；活跃迭代之间不得重叠（lint 红）。有耦合依赖的模块不并行。
- `decisions.md` / `README.md` / `glossary.md` / `sources/` 等模块根之外的共享文档不属于任何 scope，各迭代都可改写。
- 跨作用域的改动两条路：在拥有方迭代开 CH，或经 CH 裁决扩自己的 scope（CH 波及 scope 外的模块 truth 时 lint 黄）。
- 各迭代独立开、独立记变更、独立体检、独立结算；起草 CH 时冲突检查面含所有活跃迭代的 CH（见 rituals/change.md）。
- 活跃迭代数超阈值（默认 2）标黄——并行是给互不相干的工作线用的，不是用来推迟结算。
- 本次工作属于哪个迭代由任务指定；只有一个活跃迭代时不必问。

## 沉淀三分法

设计定稿 → truth（滚动改写）；重大决策 → decisions.md；过程与出处 → past/ 冻结包 + summary（考古用）。
